# План исследования

Этапы идут по порядку; у каждого — результат и критерий готовности. Номера требований — `REQUIREMENTS.md`.

## Этап 0. Прототип: одна модель, быстрые метрики (1–2 дня)

**Цель:** за минимальное время получить первые настоящие числа и проверить весь конвейер «модель в браузере → сырые выходы → метрики → CSV».

**Модель:** `blazepose-lite` (MediaPipe Pose Landmarker Lite, IMAGE-режим) — веса доступны из облачной среды уже сейчас. Запасной вариант — `movenet-lightning` (TF.js), когда откроется доступ к TF Hub/Kaggle.

**Данные:** подвыборка COCO-SinglePerson из val2017 — 300 изображений (фиксированный seed), затем вся выборка. Нужен доступ к `images.cocodataset.org`.

**Окружение:** headless Chromium (Playwright) в облаке, бэкенды CPU (WASM) и GPU (WebGL — программный, SwiftShader).

Шаги:
1. `bench/`: статическая страница + адаптер MediaPipe; раннер Playwright подаёт изображения, собирает `keypoints33`, `keypoints17`, score/visibility/presence, время на кадр; пишет `results/raw/*.json` с окружением (R5.1).
2. `eval/`: скрипт отбора COCO-SinglePerson (`docs/datasets.md`); конвертация предсказаний в формат COCO results; OKS-AP через pycocotools; PCK@0,2; KMR(τ) по суставам для τ = 0,1…0,9; FMR; задержка p50/p95, холодный старт.
3. Отчёт `docs/prototype_report.md`: таблица метрик, кривая KMR(τ), 5 худших изображений, замечания по стенду; CSV → `data/accuracy_prototype_*.csv`, `data/missing_prototype_*.csv`, `data/perf_prototype_*.csv` с пометкой `env=desktop-headless`.
4. Тестовая страница для телефона (тот же адаптер, 200 замеров на встроенном наборе из 20 изображений, кнопка «скачать CSV») — `docs/phone_quickstart.md`; автор открывает её на 1–2 своих телефонах.

**Готово, когда:** есть CSV с OKS-AP, PCK@0,2, KMR(τ), FMR, p50/p95 для BlazePose Lite на ≥ 300 изображениях COCO; AP на полной COCO-SinglePerson сопоставим по порядку с опубликованными сторонними оценками (иначе — найти ошибку стенда, а не подгонять); есть хотя бы один CSV с телефона.

**Ожидаемые подводные камни:** порядок/зеркальность точек MediaPipe (R1.4); координаты нормированы к кадру; у BlazePose нет «score» как у COCO — использовать visibility/presence, протоколировать выбор; программный WebGL в облаке медленный — скорость в облаке не является результатом.

## Этап 1. Стенд для нескольких моделей

- Адаптеры: BlazePose Lite/Full/Heavy, MoveNet Lightning/Thunder (WASM/WebGL/WebGPU), RTMPose-t/s + RTMDet-nano (ORT Web WASM/WebGPU), YOLOv8n/11n-pose (ORT Web), RTMO-s [жел.].
- `models/manifest.json` с хешами и командами конвертации (R1.2); проверка конвертации против Python-эталона (R1.5).
- Единый раннер: матрица «модель × бэкенд», рандомизация порядка, прогрев/замеры, тайм-ауты.

**Готово, когда:** все обязательные модели проходят 200 изображений COCO в headless Chromium хотя бы на одном бэкенде; расхождение с эталоном задокументировано.
