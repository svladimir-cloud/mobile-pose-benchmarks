# mobile-pose-benchmarks

Экспериментальная часть статьи «Сравнительный анализ моделей оценки позы человека для работы в мобильном веб-браузере в системе дистанционной кардиореабилитации» (текст статьи — репозиторий `svladimir-cloud/mobile-pose-article`).

Что здесь делается: лёгкие модели 2D-оценки позы (BlazePose, MoveNet, RTMPose/RTMO, YOLO-Pose) запускаются **в браузере** (MediaPipe Tasks, TF.js, ONNX Runtime Web; бэкенды WASM / WebGL / WebGPU) и сравниваются по четырём группам показателей:

1. **точность** — OKS-AP на COCO, PCK@0,2, ошибка по суставам;
2. **полнота** — доля потерянных ключевых точек (по порогу уверенности τ и по выходу за кадр), доля кадров без человека, разрывы трекинга;
3. **временная стабильность** — дрожание точек (ускорение) на статичной позе и в движении;
4. **производительность** — задержка на кадр (p50/p95), сквозная частота кадров, холодный старт, размер модели, память, троттлинг за 10 минут — на смартфонах трёх классов.

## С чего начать

| Файл | Что в нём |
|---|---|
| `STATUS.md` | текущее состояние, что сделано, что дальше |
| `PLAN.md` | план по этапам; **этап 0 — прототип** (одна модель, быстрые метрики) |
| `REQUIREMENTS.md` | требования к моделям, данным, метрикам, замерам и воспроизводимости |
| `AGENTS.md` | правила для агентов (зоны ответственности, запись по ходу, без выдуманных чисел) |
| `data/README.md` | схемы итоговых CSV, которые переносятся в статью |
| `HANDOFF.md` | как продолжить работу в новом чате |

## Структура

```
bench/      веб-стенд: страница замеров, адаптеры моделей, раннер (Playwright)
eval/       Python: метрики точности, полноты, стабильности; агрегация в data/*.csv
models/     manifest.json — источники и хеши весов (сами веса в git не кладутся)
datasets/   локальные данные (COCO, собственные видео) — в git не кладутся
results/raw сырые выходы прогонов (JSON/CSV по прогону) — в git только малые
data/       итоговые таблицы для статьи (CSV)
logs/       журнал прогонов (runs.md)
docs/       протоколы, инструкции для замеров на телефонах, отчёты
research/   progress-файлы агентов
```
