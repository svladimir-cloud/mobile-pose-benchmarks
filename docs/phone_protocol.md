# Замеры на телефонах: как запустить

Цель статьи: проверить, можно ли на большинстве смартфонов 2022 г. и новее извлекать ключевые точки локально в браузере так, чтобы корректно отслеживать выполнение упражнений. Для каждой пары «телефон × модель» стенд отвечает на три вопроса:

1. **Работает ли** — модель загрузилась, бэкенд доступен, нет зависаний (отказ — тоже результат).
2. **Достаточно ли быстро** — устойчивая частота кадров (`e2e_fps`) и её падение за 10 мин (`fps_ratio_10_1`).
3. **Достаточно ли точно для контроля упражнения** — повторы и амплитуда против эталона (`eval/exercise.py`), минимальная нужная частота — `eval/fmin.py`.

## 1. Подготовка ПК (один раз)

Нужны Python 3.11+ и Node.js 20+.

```bash
git clone https://github.com/svladimir-cloud/mobile-pose-benchmarks && cd mobile-pose-benchmarks
python -m venv .venv
```

Windows: `.venv\Scripts\activate`, Linux/macOS: `source .venv/bin/activate`.

```bash
pip install -r requirements.txt
npm ci
npm run vendor
python models/fetch_models.py
```

`fetch_models.py` скачивает веса (≈ 0,5 ГБ, вместе с эталонной моделью) в `models/cache/` и экспортирует YOLO в ONNX (для этого нужен `pip install -r requirements-yolo.txt`; без него запустите `python models/fetch_models.py --skip-yolo` — YOLO просто не будет в списке).

## 2. Тестовое видео упражнения

Положите ролик в `datasets/media/` (mp4, H.264; человек в полный рост, 10–30 с, 3–10 повторов). Если формат другой:

```bash
ffmpeg -i input.mov -c:v libx264 -pix_fmt yuv420p -movflags +faststart datasets/media/squat01.mp4
```

Затем подготовьте кадры (для точности) и эталон:

```bash
python tools/extract_frames.py datasets/media/squat01.mp4
python bench/python/run_python.py --model ref-rtmpose-x --frames datasets/media/squat01/frames.json
```

Эталон — модель RTMPose-x (не ground truth). Для статьи часть кадров стоит разметить вручную (формат COCO) и проверить по ней сам эталон.

## 3. Запуск сервера

```bash
python bench/server.py
```

В консоли появятся адрес и QR-код вида `https://192.168.x.x:8443/`. Телефон должен быть в той же Wi-Fi сети. Сертификат самоподписанный: Chrome — «Дополнительно» → «Перейти на сайт»; Safari — «Показать подробности» → «Посетить веб-сайт».

**Телефоны не из вашей сети (коллеги, участники).** Нужен публичный HTTPS-адрес. Проще всего — туннель Cloudflare без регистрации:

```bash
python bench/server.py --http --port 8080
cloudflared tunnel --url http://localhost:8080
```

`cloudflared` выдаст адрес `https://….trycloudflare.com` — его и рассылайте. Заголовки изоляции (многопоточный WASM) проходят через туннель. Результаты всё равно приходят на ваш ПК в `results/raw/`.

## 4. Условия замера (R4.4)

- Телефон не на зарядке, заряд ≥ 50 %, энергосбережение выключено, яркость фиксирована (~50 %).
- Телефон остыл (не использовался 10 мин, на ощупь не тёплый); прочие приложения закрыты.
- Во время прогона не сворачивать вкладку и не гасить экран (стенд держит экран включённым через Wake Lock, если браузер позволяет; если вкладка уйдёт в фон, прогон помечается недействительным).
- Порядок моделей рандомизируется (seed записывается); для статьи — 3 повтора в разные сеансы.

## 5. Что нажимать на телефоне

1. Открыть адрес, заполнить «Модель телефона» и «Год выпуска» (температуру — если известна).
2. **Быстрый тест** → источник «видео: squat01» → «Старт». ≈ 10 мин. Каждая модель — на лучшем доступном бэкенде; если бэкенд не сработал, пробуется следующий, отказ тоже записывается.
3. По желанию: **Полная матрица** (все бэкенды, ≈ 25 мин) — для сравнения WebGPU / WebGL / WASM.
4. **Длительный прогон 10 мин** для 1–2 моделей, которые прошли быстрый тест (обычно MediaPipe Lite/Full): источник — камера на подставке, человек выполняет упражнения в кадре; либо видео.
5. Результаты уходят на сервер автоматически. Если внизу написано «не отправлено» — «Скачать все (JSON)» и переслать файл.

Ссылка для автозапуска (удобно рассылать): `https://<адрес>/?auto=1&mode=quick&source=video:/media/squat01.mp4`.

## 6. Анализ

```bash
python eval/aggregate.py --out-csv data/perf_phones.csv --out-md docs/perf_phones.md --fmin 10
python eval/exercise.py results/raw/<прогон>.json results/raw/<эталон>.json --exercise squat --json-out ex.json
python eval/fmin.py results/raw/<эталон>.json --exercise squat --amp-thr 5
```

Порог частоты кадров для вердикта (`--fmin`) берётся из результата `fmin.py` на ваших упражнениях; 10 кадр/с — рабочее значение до этого расчёта.

## 7. Что записывается

См. `docs/result_format.md`. Видео с камеры и кадры на сервер не передаются; в режиме видео передаются координаты точек тестового ролика (нужны для оценки точности). В режиме камеры — только агрегаты скорости.
