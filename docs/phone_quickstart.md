# Замер на телефоне — быстрый старт (этап 0)

Страница: **`bench/phone/dist/phone.html`** — один файл (~3,8 МБ): адаптер BlazePose (тот же код, что на стенде), 20 встроенных изображений COCO (лицензии CC BY / CC BY-SA, список — внутри страницы, раздел «Изображения и лицензии»), кнопки «Запустить», «Скачать CSV», «Скачать JSON».
Рантайм и модель страница загружает из интернета: `cdn.jsdelivr.net` (`@mediapipe/tasks-vision@1.1.1`) и `storage.googleapis.com` (`pose_landmarker_lite.task`, 5,8 МБ). Нужен интернет на телефоне при первом запуске.

Что делает один запуск: загрузка рантайма и модели → первый инференс (холодный старт по этапам) → проход по 20 изображениям (точки сохраняются для сверки) → 50 прогревов → 200 замеров по кругу. Длительность зависит от телефона и бэкенда (в облачной эмуляции GPU — программный и медленный, ориентиром не служит).

## 1. Как открыть страницу на телефоне

**Основной способ — GitHub Pages** (репозиторий публичный):
1. GitHub → репозиторий `mobile-pose-benchmarks` → Settings → Pages.
2. Source: **Deploy from a branch**; Branch: `claude/wizardly-thompson-g1vm38` (после слияния в `main` — `main`), папка `/ (root)` → Save.
3. Через 1–2 минуты страница доступна по адресу
   **https://svladimir-cloud.github.io/mobile-pose-benchmarks/bench/phone/dist/phone.html**
   — откройте его на телефоне.

Запасные варианты:
- **Любой статический HTTPS-хостинг:** скачайте `bench/phone/dist/phone.html` и перетащите папку с ним на https://app.netlify.com/drop.
- **Ноутбук в той же Wi-Fi-сети:** в клоне репозитория `HOST=0.0.0.0 PORT=8080 node bench/server.mjs`, на телефоне — `http://<IP ноутбука>:8080/bench/phone/dist/phone.html`.

Если страница пересобиралась (`node bench/phone/build.mjs`, нужны изображения в `datasets/coco/val2017/`), в CSV меняется `page_version`.

## 2. Условия (R4.4)

- телефон остыл (не использовался 10+ мин), **не на зарядке**, заряд ≥ 50 %, энергосбережение выключено, яркость ~50 %, прочие приложения закрыты;
- экран не гасить и не переключаться на другие вкладки во время замера (если страница ушла в фон, запуск помечается `invalid`);
- **холодный старт честный только у первого запуска после загрузки страницы** — перед каждым запуском перезагружайте страницу (страница предупредит, если это не так).

## 3. Порядок замеров (на каждом телефоне)

1. Заполните «Телефон (модель)» (например, `Samsung Galaxy A54`), при желании — температуру; заряд подставляется сам там, где браузер это умеет (Android Chrome), иначе введите вручную. В «Заметке» — браузер и условия.
2. Бэкенд **CPU (WASM)** → «Запустить» → дождитесь «Готово» → **«Скачать CSV»** (и при желании «Скачать JSON» — там же точки по 20 изображениям).
3. Перезагрузите страницу → бэкенд **GPU (WebGL)** → «Запустить» → «Скачать CSV».
4. Если есть второй браузер (Яндекс Браузер на Android, Safari на iOS) — повторите 2–3 в нём.
5. Для этапа 0 достаточно одного повтора; по протоколу (R4.4) позже нужно 3 повтора в разных сеансах.

Имя файла: `<время>_<телефон>_blazepose-lite_<бэкенд>.csv`.

## 4. Куда отдать файлы

Пришлите CSV (и JSON) в чат или положите в репозиторий в `results/raw/phone/`. Дальше:
```bash
python3 -I eval/phone_to_perf.py results/raw/phone/*.csv --out data/perf_phone_prototype.csv
```
— даст строки в схеме `data/README.md` (`env=phone`, p50/p95, холодный старт по этапам, браузер/ОС из user agent).

## 5. Формат CSV

Одна строка на измерение; столбцы окружения повторяются в каждой строке: `run_id, date, env=phone, page_version, device, note, user_agent, model, variant, runtime, runtime_version, backend, delegate, wasm_simd, wasm_threads, webgl2, webgpu, webgl_renderer, hardware_concurrency, battery_pct, temp_c, run_in_page, n_warmup, n_measure, status`, затем `phase` (`cold_import_ms` / `cold_load_ms` / `cold_init_ms` / `first_infer_ms` / `pass20` / `measure`), `i`, `image_id`, `latency_ms`, `detected`.

## 6. Если что-то не так

- «Ошибка: failed: …» — пришлите скриншот и JSON; частые причины: нет доступа к `cdn.jsdelivr.net` или `storage.googleapis.com`, GPU-бэкенд не поддерживается (это тоже результат — R4.3).
- Проверка страницы в облаке (эмуляция Pixel 7, без реального телефона): `node bench/phone/test_phone.mjs --backend wasm` — только проверка работоспособности, не замер.
