# Прогресс: агент eval

## Решения
- Отбор COCO-SinglePerson: ровно одна аннотация на изображение (все аннотации в person_keypoints — person; crowd тоже считаются аннотациями), iscrowd=0, num_keypoints>=1 -> **921** изображение. Без условия num_keypoints>=1 (ровно одна аннотация, iscrowd=0) получается **1045** — это число авторов RTMPose; расхождение в 124 изображения — аннотации с num_keypoints=0. Опция `--min-keypoints 0` воспроизводит 1045. По заданию используем 921.
- coco_eval по умолчанию считает только по изображениям, присутствующим в предсказаниях (удобно для подвыборок, напр. 300 изображений); `--all-gt` — по всему GT. Изображение с `kps=null` входит в расчёт как «человек не найден».
- Бутстреп AP: пересэмплирование изображений с возвращением; вместо повторного COCOeval переиспользуются evalImgs (сопоставление в COCOeval независимо по изображениям) и своя копия accumulate (area=all, maxDets=20); проверено в тесте, что на полной выборке совпадает с COCOeval. ДИ — 2.5–97.5 перцентили.
- PCK: порог «<= 0.2 * диаметр торса»; score точки в PCK не используется (порог tau — только в KMR).
- Площадь под KMR(tau): трапеции по tau=0.1..0.9, делённая на 0.8 (т.е. среднее KMR по кривой, 0..1).
- tau* для 10% пропусков: наибольшая tau на сетке 0.01, при которой общий KMR <= 10%.
- Столбцы CSV сверх схемы data/README.md добавлены в конец (err_*_lostinf, fmr, n_pck_images, kmr_auc, tau_star_10, kmr) — схему не ломают.
- Предсказания out-of-frame: x<0 или x>=width, y<0 или y>=height.

### Решения по exercise.py
- Допуск сопоставления кадров: половина медианного периода кадров эталона (если эталон 30 к/с -> ±16.7 мс).
- Углы и повторы считаются по точкам с score >= `--min-score` (по умолчанию 0.3) и у прогона, и у эталона; для CKMR используется переменный tau.
- Основной угол: для squat/knee_flexion — колено, arm_raise — плечо (бедро-плечо-локоть), elbow_flexion — локоть; `--side both` = среднее по доступным сторонам.
- Повторы: скользящее среднее 0.15 с (в кадрах — по частоте кадров серии; при низкой частоте окно 1), пороги low/high = 30%/70% размаха эталона (перцентили 2–98 сглаженного угла эталона), одни и те же пороги для прогона и эталона. Повтор = выход в зону, противоположную начальной, и возврат в начальную (работает и для приседа — старт «высоко», и для подъёма рук — старт «низко»). Если размах эталона < 10° — повторы не считаются.
- Сопоставление повторов: экстремум повтора прогона должен попасть в интервал повтора эталона (с запасом 25%); амплитуда = экстремум (min или max угла за повтор).
- CKMR: k=1 по умолчанию (потеряна хотя бы одна точка упражнения); разрывы — серии подряд идущих кадров прогона с потерей при данном tau; в мс — через медианный период кадров прогона.
- LR-swap: кадр с обменом, если сумма расстояний при обмене сторон < половины суммы без обмена, по 8 симметричным парам (точки без NaN, score не учитывается).
- fmin.py, jitter.py написаны. Решения: f_min = минимальная частота, начиная с которой условие (худший фазовый сдвиг: ошибка повторов 0, MAE амплитуды <= порога) выполняется и для всех более высоких проверенных частот. Статика: медиана по суставам скорости (длин торса/с) < 0.1 (сглаживание 0.5 с), самый длинный отрезок >= 3 с; детекция — по эталону (--ref), иначе по самому прогону. Движение по умолчанию — более длинная из частей клипа вне статичного отрезка. J_acc в px/кадр² без учёта неравномерности времени (вторая разность по соседним кадрам); нормировка на длину торса (jacc_norm) — доп. столбец. Лаг фильтра — кросс-корреляция по всему ряду (параболическое уточнение), положительный = фильтр запаздывает.
- aggregate.py написан. Решения: устройство = user_label, иначе ua_model; пары группируются по (устройство, env, модель, вариант); лучший бэкенд = max e2e_fps среди ok; для вердикта точности нужны JSON exercise.py (--exercise-json; сопоставление по device/env/model/variant/backend из блока run). Доля пригодных считается по env=phone (desktop-headless не смешивается).
